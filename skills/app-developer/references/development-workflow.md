# 开发、打开与验收流程

每步留本轮证据；失败停在当前阶段，修复后从受影响阶段重验。主提示保持精简；SDK细节读 host-sdk.md 和同源 sdk/README.md。

## 1. 定义产品
- 核心任务、最少输入、可用成果、数据归属；五类路径读 instant-types.md。
- 新增以一句必填意图为主，可选粘贴素材；话术等内容工具编辑保留标题＋内容。分类/标签/摘要/命名等派生字段由AI整理，不要求用户先建分类体系；禁止分类下拉、标签输入等管理表单。用户明确内容优先；AI无法推断的真实业务事实按需采集，不机械限制所有业务字段数。
- 页面不以关键词匹配、固定模板冒充语义智能；技能写清领域知识、分类规则和失败处理，由模型执行并读回真实记录。
- 复制、搜索、分页、校验、游戏实时交互直接执行；语义任务调用AI。禁止所有按钮都等模型，或把AI只做成表单旁的装饰按钮。
- 查看同类开源方案与许可；视觉检索可选，查则用最新同类资料，例如 Awwwards、Mobbin、优秀产品官网；游戏/办公按场景定风格。

## 2. 约定实现
- 简单本地即用先读 [local-app-structure.md](local-app-structure.md)：HTML/CSS/原生 JS，规划页面、公共组件、数据访问边界，直接挂载容器；Web 服务/H5 可用 Vue、React 等，不受本地技术栈约束。
- 读取实际 SDK、权限、MCP inputSchema；列出页面动作→SDK方法→技能→存储→回执。没有接口不编造，缺能力明确阻塞。
- 文件导入/上传先读 [local-files.md](local-files.md)，明确会话附件、持久素材与业务上传；实现原生选择、取消/移除、失败保留、受理后释放、切范围隔离与真实业务读回，并纳入安装后验收。
- 智能联动先读 [intelligent-interaction.md](intelligent-interaction.md)：必须将联动契约写入所开发即用的instructions/随包业务技能，并同步实现页面的接收、校验、回填、应用及结果追踪；明确消息后应用或直接更新、确认范围。两端必须配套交付和验收，不能只交付聊天答复或刷新占位。
- template:app；默认包内相对资源。宿主加载安装版本，注入原生桥；无需网页主动 connect；权限在 source.bridge.capabilities 声明。
- AI路径先选：提词/改写/分类等用ai.generate，界面直接回显；只传当次输入及技能提示词，不走规划或新会话；查资料/工具执行用chat.send。详见fast-ai.md。
- 业务技能物理随包、真实加载：意图路由、读取范围、处理步骤、数据不变式、CAS/幂等写回、读回回执。instructions 引用真实资源；skills 字段只填宿主真实注册技能，不能把文件路径冒充技能名。
- 本机数据使用宿主 SQLite；初始化脚本/种子/升级迁移随包；界面缓存只存可丢弃偏好。无需为每个静态即用启动服务。外部服务只在业务需要时使用，部署与安装分别验收。

## 3. 实现与静态检查
- 检查单个 HTML/JS 的长度与职责：目标300～500行，800行作为评审提醒；按清晰边界拆分页面和公共组件，不压缩排版凑行数。内部页面复用直接 mount 到 div，切换时清理旧事件/请求，避免 iframe 层层嵌套。
- 先读已有文件再定点修改，避免反复整文件重写；核对 HTML ID、事件绑定、全局变量、脚本顺序及重复声明。
- 对最终磁盘草稿运行 scripts/validate.cjs；它验证包/资源/声明及随包 JS 语法，不执行作者脚本，不能证明 DOM、桥、AI 或业务成功。
- 初始化/修订号/分页/失败路径做实际验证：第一页省略 after；翻页只用非空 next；禁止空字符串充当记录ID。
- 修改提升 SemVer；保留稳定 key、用户数据、已有元数据；导出后在无源码副本环境导入，验证包完整。

## 4. 开发预览
- 有多页面时验证来回切换、同模块复用、输入保留和迟到响应隔离；确认没有重复绑定、CSS/ID冲突或多余滚动条。
- 可用本地 HTTP 静态预览（scripts/serve.cjs）；这只是开发工具，不能作为包内即用交付依赖。
- file:// 的 CSS/JS/XHR 失败先看控制台/网络请求；可换HTTP定位。安全软件加密仅在有证据时归因，不规避安全策略；文字乱码先确认编码/保护，使用能正常读取的受信工具。
- 捕获启动异常/未处理拒绝/加载失败；点击每个核心按钮并核对结果；空态、中英文、窄屏。截图失败与业务失败分开重试，不能因截图超时重复写入/发送。
- 无宿主只提供明确演示模式，样例放内存，禁用不可用AI/保存动作；预览不产生正式业务数据，不能声称已连接。

## 5. 宿主安装与打开（必验）
- 检查当前会话实际成果→检查并安装→即用列表→打开安装版本；记录 key/版本与资源摘要，不以源码预览冒充安装包验收。
- 声明 context.read，调用 context.get 确认宿主；再分别测 settings/data/AI。SDK对象存在不代表连接；context正常而data失败应报告数据错误。
- 没有 soduWorkApp.connect()；mcp.connect 是在线业务MCP接入，不是壳握手。本机 soduwork-jiyong 由宿主按安装版本接入，不需要页面手动连接。
- 接口 reject 或 ok:false 保留 reason/阶段并提供重试，禁止空 catch 后切浏览器存储。2.5秒无回应只能表示等待/超时；不能证明无壳，也不能证明写操作未发生。重试使用原 requestId，先核对实际结果。
- 实测核心意图→右侧对话→随包技能→真实MCP→写回→读取显示；发送受理/轮次结束不算业务完成。失败保留输入，异步结果核对请求ID/当前输入版本，避免覆盖新编辑。
- 涉及联动时实测成果回填、通知/直接更新、确认后执行与真实回执；重复消息、并发修改、迟到结果、失败/取消及重开补读见 intelligent-interaction.md。简单 ai.generate 路径在页面内验收，无须人为增加右侧对话。
- 再测分页、CAS冲突、刷新、关闭重开、升级保留数据、多窗口不串会话；持续角色另测关窗后计划执行与结果回看。涉及真实服务/模型时只按实际授权执行，缺条件写明未测。

## 6. 修复与交付
- “检查并安装”只校验包结构、权限声明、资源完整性及数据声明，云端声明另做只读就绪检查；安装时不启动页面、不做首屏预检或截图。开发者按需进行原生运行诊断与业务验收，不能把包校验通过当作业务完成。
- 现有“立即修复”会向该开发会话发送失败信息并重检；运行错误也应带上方法/阶段、堆栈、安装版本与复现步骤，发起有范围的一轮修改。重检同一最终候选包；仍失败明确保留问题，不能无限循环/假装完成。
- 新错误先定位到文件/契约，再改动；不得用兼容别名掩盖虚构SDK调用。凭据/离线/设备缺失按配置或环境处理，不盲改代码。
- 交付分列：静态检查、开发预览、原生安装、真实AI/业务、关窗任务、未测项；质量通过后登记当前会话成果。不得用历史或夹具证据宣称真实生产通过。

## 7. 数据位置与云端预检

创建入口必选“数据云存储/数据本地化”，其选择进入开发提示词；生成前读取 [cloud-data.md](cloud-data.md)，把 location 显式写入 jiyong.storage，提供包内初始化 JSON。新建数据即用使用 `scaffold.cjs --storage local` 或 `--storage cloud`；不能擅自替用户改变位置。静态校验检查声明/初始化/迁移，宿主预检还只读检查云端就绪。隔离首屏使用本地替身并标注证据，不能当作云端写入验收。安装后自动开通与初始化；真实云端业务须写回读回、换设备同账号补读、关窗重开后才验收，不以预检成功代替。云端失败不得降级 localStorage 或 SQLite。
